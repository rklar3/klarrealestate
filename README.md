# Klar Real Estate

Marketing and lead-generation site for Klar Real Estate — Sanam Klar, REALTOR® with
Oakwyn Realty, serving the Okanagan Valley (Kelowna, West Kelowna, Penticton, Vernon,
Summerland).

Next.js (App Router) + TypeScript + Tailwind CSS v4.

## Setup

```bash
npm install
cp .env.example .env.local   # fill in the values described below
npm run dev
```

Open [http://localhost:3000](http://localhost:3000).

## Environment variables

See `.env.example` for the full list with inline comments. Summary:

| Variable | Required | Purpose |
| --- | --- | --- |
| `NEXT_PUBLIC_SITE_URL` | Yes | Canonical domain, used in metadata, sitemap, JSON-LD. No trailing slash. |
| `RESEND_API_KEY` | For live lead delivery | [Resend](https://resend.com) API key. Without it, form submissions are validated and logged server-side but not emailed. |
| `LEAD_FROM_EMAIL` | No | Verified "from" address for lead emails sent via Resend. |
| `NEXT_PUBLIC_GA_ID` | No | Google Analytics 4 measurement ID. Omit to skip GA4 entirely. Vercel Analytics is always on and needs no config when deployed on Vercel. |
| `DDF_CLIENT_ID` / `DDF_CLIENT_SECRET` | For live listings | CREA DDF® data feed username/password (from the CREA DDF® Team email). Server-only. Without them, listing pages render empty. |

## Editing content

Almost everything content-related lives in `data/` and `content/` as plain TypeScript/MDX —
no CMS, no database.

- **Business facts (NAP, socials, service areas):** `data/site.ts` — single source of truth,
  used by the footer, contact page, and JSON-LD.
- **Listings:** live from CREA DDF® — see "Live listings (CREA DDF®)" below. Not edited by hand.
- **Area guides:** `data/areas.ts`, one object per community. To add a new service area, add
  an entry here (and to `serviceAreas` in `data/site.ts`) — `/areas/[area]` picks it up
  automatically via `generateStaticParams`.
- **FAQs:** `data/faqs.ts`.
- **Testimonials:** `data/testimonials.ts` — currently placeholder examples, clearly marked.
  Replace with real, permissioned client quotes before launch.
- **Placeholder images:** `public/images/*.svg`, generated by
  `scripts/generate-placeholder-images.mjs`. Swap in real photography by replacing the file at
  the same path (e.g. `public/images/kelowna.svg` → a real `.jpg`/`.webp`, updating the
  `image` field in `data/areas.ts` to match). Listing photos come from the DDF feed.

## Adding a blog post

Posts live in `content/resources/*.mdx` as frontmatter + MDX body, read at build/request time
by `lib/posts.ts` (no database).

1. Add a new `.mdx` file to `content/resources/`.
2. Frontmatter fields: `title`, `description`, `date` (`YYYY-MM-DD`), `draft` (optional boolean).
3. Set `draft: false` (or omit it) to have the post appear in `sitemap.xml` and be indexable;
   `draft: true` posts still render (marked "Example / draft" in the UI) but are excluded from
   the sitemap and set to `noindex`.

The three starter posts included are example content only, marked `draft: true` — replace with
real posts before launch.

## Live listings (CREA DDF®)

Listings come from Sanam's REALTOR.ca DDF® Web API feed (destination "Member Website Feed - One
or More Offices", ID `67413`), which returns the active listings of Sanam's Oakwyn Realty
office. [API docs](https://ddfapi-docs.realtor.ca/).

- `lib/ddf.ts` — server-only API client: OAuth client-credentials token from
  `identity.crea.ca` (60-minute tokens, reused in memory) and paged OData reads from
  `ddfapi.realtor.ca`.
- `data/listings.ts` — maps DDF `Property` records to the site's `Listing` shape and caches
  the whole feed for 1 hour (`unstable_cache`, tag `ddf-listings`). A failed refresh keeps
  serving the last good copy. `getListings()`, `getListingBySlug()`, `getFeaturedListings()`
  and `filterListings()` are the only entry points pages use.
- Sanam's own listings (matched on `siteConfig.ddf.memberKey`) sort first and get a badge;
  `/listings?agent=sanam` shows only those (the listings page toggle and the homepage hero link
  there).
- Listing URLs are `/listings/<address>-<city>-<MLS number>`; lookups match on the trailing
  MLS® number and 308-redirect to the current slug if the address text changes.
- Listing pages, area pages, the homepage, and the sitemap revalidate hourly.

DDF® display rules handled in the UI: a clickable "Powered by: REALTOR.ca" badge linking to the
listing on REALTOR.ca, the listing brokerage/agent on every listing, the CREA trademark notice
in the footer, and a data-source disclaimer. Listings flagged
`InternetEntireListingDisplayYN = false` are dropped, and addresses flagged
`InternetAddressDisplayYN = false` are hidden. Photos carry CREA's watermark top-left, so
overlays sit top-right.

Not yet implemented: CREA's listing-view analytics beacon (`analytics.crea.ca`), which feeds
view stats back to listing agents.

## Forms & lead delivery

`/api/contact` and `/api/valuation` are Next.js Route Handlers that validate input with Zod,
apply a honeypot field and a simple in-memory rate limit, then send the lead via
[Resend](https://resend.com) (`lib/email.ts`) to the address in `data/site.ts`. To swap in a
different email provider (e.g. Nodemailer), only `lib/email.ts` needs to change.

A commented hook in `lib/email.ts` marks where to POST the same lead payload to a CRM (Follow
Up Boss, kvCORE, etc.) once one is chosen.

## Tech stack

Next.js 16 (App Router, Turbopack), React 19, TypeScript, Tailwind CSS v4 (tokens defined via
`@theme` in `app/globals.css` — Tailwind v4 is CSS-first and does not use `tailwind.config.ts`),
Zod, Resend, Radix UI primitives, next-mdx-remote.

## Deploy

Deploy target is Vercel. Push to a connected repo or run `vercel deploy`; set the environment
variables above in the Vercel project settings before the first production deploy.
